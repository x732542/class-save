## Part 1 — 會議必須敲死的 12 件事

沒拍板 = 翻車。

### ① Schema Owner（單人獨裁）
**問題**：6 人一起改表結構，schema 永遠對不齊。
**解法**：指定 1 人專職管 `CREATE TABLE` 與 seed data，其他 5 人只寫 SP 不碰表結構。需要改表必須走這個人。

### ② SP 命名不撞車
**問題**：A 和 C 都想寫 `usp_get_user`。
**解法**：按 domain 切前綴，每人領一個 domain。
範例：`usp_member_*` / `usp_health_*` / `usp_activity_*` / `usp_food_*` / `usp_goal_*` / `usp_report_*`

### ③ 參數與回傳格式統一
**問題**：有人用 OUTPUT 參數、有人用 RETURN code、有人 SELECT，合起來亂七八糟。
**解法**：**統一用 SELECT 回傳資料集**（老師範例就是這樣）。每個 SP 最後至少 SELECT 一欄 `status INT`（1=成功 / 0=失敗）。查詢型 SP 再額外 SELECT 資料列。
**⚠️ 待確認**：老師範例「以資料集方式傳回1：成功0：失敗」曖昧，究竟是單一值還是資料集+status？會議時問組員有沒有老師其他範本，沒有就按本計畫走。

### ④ SQL Server 版本地雷
**問題**：有人 2014、有人 2022，`STRING_AGG` / `TRIM` / `IIF` 這些在舊版跑不動。
**解法**：會議時全員報版本，以最舊那台為基準。建議公告：**一律 2017+**，並禁用 2019 後的新語法（例如 JSON_OBJECT）。

### ⑤ Demo 主機早點決定
**問題**：4/20 當天誰的電腦上台？那台要能一鍵重建整個 DB。
**解法**：會議先問志願，demo 主機的人 = Schema Owner 最自然（他本來就要維護整合腳本）。如果不同人，Demo 主機要在 4/19 rehearsal 前跑過 total.sql 確認 OK。

### ⑥ 整合腳本檔名編號
**問題**：6 個 .sql 檔丟進資料夾，誰先跑誰後跑？
**解法**：
```
00_drop.sql              -- A 寫（清掉舊 DB 方便重跑）
01_schema.sql            -- A 寫（所有 CREATE TABLE）
02_seed.sql              -- A 寫（測試資料）
03_procs_member_<B初名>.sql
04_procs_health_<C初名>.sql
05_procs_activity_<D初名>.sql
06_procs_goal_<E初名>.sql
07_procs_report_<F初名>.sql
99_demo_script.sql       -- 全員協作（demo 當天跑的 EXEC 順序）
```
檔名含初名避免覆蓋。編號決定執行順序。

### ⑦ 測資依賴
**問題**：E 寫 streak SP 需要一週的步數資料才能測。但測資是 A 的工作。
**解法**：A 的 seed.sql 必須**至少涵蓋所有人 SP 需要的情境**。會議時每人講：「我的 SP 需要什麼資料存在」，A 彙整進 seed。

### ⑧ 工作量對齊
**問題**：有人寫 6 個 SP，有人寫 1 個，demo 時時間分配也爆。
**解法**：20 分鐘 demo ÷ 6 人 = 每人 ~3 分鐘。每人 **2~3 個 SP**，全組共 **12~15 個**。不要貪多。

### ⑨ Demo 劇本不是「SP 逐個叫一遍」
**問題**：老師最不想看「demo 就是 exec 每個 SP 一次」。
**解法**：寫一個**真人情境腳本**，例如：
> 王小明註冊 → 記錄今天步數 8000 → 昨天體重 72kg → 查週報「達標率 5/7」→ 修改目標為每日 10000 步 → 再查週報

這樣 SP 被串起來用，自然流。**每個 SP 至少在劇本裡被呼叫一次**。
**操作模式**：一人坐主控（A），其他人螢幕掌聲自己 SP 被呼叫時接手講解 3 分鐘，講完滑鼠還給 A。

### ⑩ SSMS 截圖不是我能代勞的
**問題**：簡報裡要放「SP 執行結果漂亮截圖」，老師看這個判斷 demo 可行性。
**解法**：4/19 中午前全員各自截自己寫的 SP 執行結果（SSMS 的結果區塊），丟共用資料夾。不要留到 rehearsal 才截。

### ⑪ 備案（最容易被忽略）
- Demo 主機當天 SQL Server 服務沒開 → 事先開機檢查 + 關掉 Windows Update 自動重啟
- 投影線接不上 → 準備 HDMI / Type-C 雙轉接
- Demo 跑到一半某個 SP 爆 → 4/19 rehearsal 同時錄全程影片當 backup
- 有人 4/20 發燒請假 → 他的 SP 說明頁每人都要會講一句
- total.sql 帶一份在 USB，離線可跑

### ⑫ 亮點 business rule（一顆就好）
⭐️⭐️ 只做「CRUD 體重步數」會很無聊。**只做 1 顆**，建議 E 的 **streak 連續達標天數**：
- 邏輯：抓這個會員最近 N 天步數紀錄，從今天往前數，連續達到目標的天數
- 老師會問的延伸：「如果中間有一天漏打卡呢？」→ 準備答「漏記視為未達標，符合真實情境」

## Part 5 — 命名規範（今天必須拍板）

### 資料表
- PascalCase 單數：`Member`、`HealthLog`、`Activity`、`ActivityType`、`FoodLog`、`Goal`
- 主鍵統一 `<Table>Id`（MemberId、HealthLogId），INT IDENTITY(1,1)
- 建立時間欄位統一 `CreatedAt DATETIME2 DEFAULT SYSDATETIME()`

### Stored Procedure
- 小寫底線：`usp_<domain>_<action>`
- action 動詞：`register` / `login` / `insert` / `list` / `update` / `delete` / `report` / `check`
- 範例：
  - `usp_member_register`
  - `usp_health_insert`
  - `usp_health_list_by_date`
  - `usp_goal_check_streak`

### 參數
- `@camelCase`，與老師範例 `@uid @pwd` 短名風格並用
- 範例：`@memberId`、`@uid`、`@pwd`、`@startDate`、`@logDate`、`@weightKg`
- ⚠️ 老師範例用 `@uid @pwd`，登入/註冊 SP 就照這個風格，其他 SP 用 camelCase

### 回傳
- 查詢型 SP：**先 SELECT 資料集，最後 SELECT status**（SSMS 顯示兩個結果分頁）
- 動作型 SP（insert/update/delete）：只 SELECT `status, message`（status=1 成功、0 失敗）
- 所有 SP 外層包 `BEGIN TRY ... BEGIN CATCH`，catch 回傳 status=0 + ERROR_MESSAGE()

### 檔案
- UTF-8 with BOM（SSMS 預設）
- 每個 .sql 開頭先 `USE HealthDB;` + `GO`
- 每個 CREATE PROCEDURE 前加 `IF OBJECT_ID('usp_xxx') IS NOT NULL DROP PROCEDURE usp_xxx; GO`（才能重複執行）

## Part 6 — ER 骨架建議（A 可當起點）

六張表對應五個 domain + 一張參照表：

```
Member (MemberId PK, Uid 唯一, Pwd, Name, Gender, Birthday, HeightCm, CreatedAt)
  │
  ├── HealthLog (HealthLogId PK, MemberId FK, LogDate, Steps, WeightKg,
  │              CaloriesIntake, CaloriesBurned, CreatedAt)
  │
  ├── Activity (ActivityId PK, MemberId FK, ActivityTypeId FK, DurationMin,
  │             CaloriesBurned, ActivityAt, Note)
  │
  ├── FoodLog (FoodLogId PK, MemberId FK, FoodName, Calories, MealType, EatenAt)
  │
  └── Goal (GoalId PK, MemberId FK, GoalType, TargetValue,
            StartDate, EndDate, IsActive)

ActivityType (ActivityTypeId PK, Name, MetValue)
  └── 被 Activity 參照，例：跑步/走路/游泳/騎腳踏車
```

- `Activity.ActivityTypeId` FK → `ActivityType.ActivityTypeId`
- 參照表讓 demo 多一個 JOIN，也讓新增運動類型不用改表
